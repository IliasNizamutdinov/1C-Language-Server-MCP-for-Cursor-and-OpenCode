# Устранение неполадок

| Проблема | Вероятная причина | Что сделать |
| --- | --- | --- |
| Сервер не запускается | Не найден Python, не установлен пакет `mcp` или ошибка в команде | В том же окружении выполните `python -m bsl_mcp --version`. Ожидается `0.1.0`. Затем `python -m pip install -e ".[dev]"` из корня репозитория. |
| Java не найдена или `java -version` показывает не 21 | В `PATH` нет JDK 21 | Нужна Java 21. Установите JDK 21, откройте новое окно PowerShell и проверьте `java -version`. Если видна другая версия, укажите полный путь к `java.exe` из JDK 21 в `BSL_JAVA`. |
| `UnsupportedClassVersionError`, class file version 65.0 | Запущен Java 17 или старше, а jar 1.0.7 собран для Java 21 | Установите JDK 21. В новом окне PowerShell `java -version` должна показать 21. Если видна 17, задайте `BSL_JAVA` полным путём к `java.exe` из JDK 21. Jar заново скачивать не нужно. |
| Анализатор не найден | Пустая или неверная `BSL_LANGUAGE_SERVER_JAR` | Укажите путь к `bsl-language-server-1.0.7-exec.jar`, не к маленькому jar без зависимостей и не к zip-архиву. `java -jar <путь> version` печатает `version: 1.0.7`. |
| Cursor не видит инструменты | Неверный `mcp.json`, сервер выключен или процесс сразу завершился | Проверьте Output → MCP Logs. В конфигурации должны быть `command` и `args`, тип `stdio`. Перезагрузите окно. |
| OpenCode не видит инструменты | Конфигурация скопирована из Cursor или `timeout` слишком мал | Используйте объект `mcp` и `type: "local"`, а `command` задайте массивом. Увеличьте `timeout` до `15000`. |
| Ошибка разбора JSON | Лишняя запятая или комментарий в JSON | Cursor принимает только JSON. OpenCode в документации показывает и JSONC, но образец в этом репозитории — обычный JSON. Проверьте файл на https://jsonlint.com или командой `python -m json.tool file.json`. |
| Повреждён STDIO | В stdout попали обычные логи | Сервер пишет журналы в stderr. Не запускайте адаптер через оболочку, которая печатает приветствие в stdout. Не ставьте `print` в код сервера. |
| Таймаут | Большой каталог или медленный первый запуск Java | Увеличьте `BSL_MCP_TIMEOUT`. Для проекта укажите каталог с модулями, а не весь диск. При таймауте процесс Java и его дочерние процессы завершаются, статус будет `not_performed`. |
| Файл не поддерживается | Расширение не `.bsl` и не `.os`, либо это `.cf` / `.cfe` / `.epf` / `.erf` | Выгрузите модули в исходники. Двоичная выгрузка конфигурации напрямую не анализируется. |
| Проверка не выполняется | Путь вне `BSL_MCP_ALLOWED_ROOTS`, нет прав или анализатор завершился с ошибкой | Статус `not_performed` и текст в `summary`. Сверьте корень в переменной и абсолютный путь файла. |
| Синтаксическая ошибка не обнаружена | Анализатор восстановил разбор либо конструкция ему неизвестна | BSL Language Server 1.0.7 не сообщает `ParseError` для файла, в котором есть только `КонецПроцедуры`. Смотрите не только статус, но и массив `diagnostics`. Отсутствие диагностики не равно проверке платформой 1С. |
| Агент не вызывает проверку | Правила проекта не гарантируют вызов | Назовите инструмент в запросе: `используй check_bsl_file`. Повторите правило в `AGENTS.md` или `.cursor/rules`. |
| Проверка фрагмента ограничена | `check_bsl_code` не видит конфигурацию | Это ожидаемый статус `limited`, если синтаксических ошибок нет. Для полного файла на диске используйте `check_bsl_file`. |
| После обновления анализатора изменился результат | Новый релиз BSL Language Server изменил диагностику | Закрепите проверенную версию 1.0.7 или заново прогоните `pytest`. Адаптер не подменяет текст диагностики своим. |
