# Инструкция агенту: проверка BSL после изменений

Скопируйте этот текст в `.cursor/rules/bsl-syntax-check.mdc` или в `AGENTS.md` проекта 1С. Готовые файлы уже лежат в корне этого репозитория.

Инструкция не включает автоматический хук. Клиент может её проигнорировать. Если нужна уверенность, явно попросите вызвать инструмент.

1. Перед правкой прочитай модуль и зависимости, которые затрагивает изменение.
2. После создания или правки `.bsl` / `.os` вызови `check_bsl_file`. Для текста, который ещё не записан, вызови `check_bsl_code`.
3. Прочитай все диагностики: файл, строка, столбец, серьёзность, код и сообщение.
4. Исправь синтаксические ошибки, связанные с твоими изменениями.
5. Повтори проверку.
6. Если ошибки остались, исправь их и проверь ещё раз.
7. Сообщи пользователю, что найдено, что исправлено и какие ограничения остались.
8. Не говори, что проверка пройдена, если инструмент не запускался.
9. Не говори, что проверка пройдена при статусе `failed` или `not_performed`.
10. Инструмент проверки сам код не меняет.

Отдельного проверенного автоматического запуска после каждого сохранения в Cursor или OpenCode этот проект не настраивает. Вызов делает агент по инструкции либо по прямой просьбе пользователя.

Если пользователь просит только проверить уже существующий код, вызывай `check_bsl_file` или `check_bsl_files` и не меняй файлы.

Если код написан тобой в этом же ответе, проверь его до завершения задачи. До записи в файл используй `check_bsl_code`, после записи и после каждой правки — `check_bsl_file`. При статусе `failed` исправь синтаксис и повтори проверку. Статус `limited` не заменяет последующий `check_bsl_file`.
